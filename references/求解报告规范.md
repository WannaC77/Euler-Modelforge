# 求解报告规范（E-M4 · 求解输出规范）

> **用途 / Purpose**：规定一次求解「交付什么、怎么写、怎么自证」——基线纪律、改进四件事、报告节结构、数值自检与模板冒烟要求。
> **对应工作流 / Workflow**：`workflows/05-编程求解.md`（正本：§代码规范 / §数据来源与处理交代 / §算法改进合规 / §ML 任务纪律 / §结果验证）；配套 `templates/复现卡.md`、`templates/敏感性报告卡.md`
> **门禁指针 / Gates**：`Euler-ENGINE.md` §1 **E-M4**（求解工坊）——模板冒烟 rc=0；种子固定；报告卡齐；改进四件事（基线/改动/量化/公平对照）；`_SHARED.md` 硬门禁 5/6/7；§3「求解」行
> **降级 / Fallback**：手写脚本 + 人检；缺 venv → 系统 Python 并声明（`[降级]`）

---

## 1 · 一次求解的交付物（最小集）

| # | 交付物 | 形态 | 落盘 | 门禁 |
|---|---|---|---|---|
| 1 | 可复跑脚本 | `.py`（参数化、换数据能跑） | `scripts/` | 一条命令可跑（见复现卡 §3） |
| 2 | 求解报告节 | Markdown（§3 的四个小节） | 本报告 / 论文素材 | 四节齐 |
| 3 | artifacts | 数值表/JSON/日志/图 | `artifacts/RC-<N>/` | 复现卡产物列逐项存在 |
| 4 | 复现卡 | `templates/复现卡.md` 填毕 | 随报告 | 环境/数据版本/命令/预期数值/差异容忍齐 |
| 5 | 敏感性报告卡 | `templates/敏感性报告卡.md` 填毕 | 随报告 | 扫的参数全呈现 + `[E3]` 互验 ≥1 |

## 2 · 基线纪律

**基线 = 你会拿来做对照的那个「朴素/原版」实现**，必须真实跑出来，不是纸面描述。

| 情形 | 基线是什么 | 备注 |
|---|---|---|
| 用现成模型/模板 | 该模板的默认参数版本（同数据、同参数预算） | 基线也调参（见 §3-④） |
| 提出改进算法 | 原版算法实现 | 硬门禁 7 强制 |
| 做模型融合 | 最优单模型 | `workflows/04` §模型融合 |
| 无改进主张 | 写「本次为基线实现，无改进主张」 | 不适用硬门禁 7，但报告节仍要齐 |

- 基线数据与改进版**必须同一份数据、同一评价指标、同一测试划分**（`_SHARED.md` 硬门禁 7）。
- 没有同条件基线对照数据 → **不写**「改进 X 优于 Y / 融合优于单模型」类主张。

## 3 · 改进四件事（缺一不可）

（正本：`workflows/05` §算法改进合规；`Euler-CORE.md` 思维铁律⑧）

| # | 事 | 具体要求 | 留证 |
|---|---|---|---|
| ① | **基线对照** | 原版 X 算法实现出来，同数据、同参数预算下运行 | 基线运行的脚本 + 结果 artifact |
| ② | **改动说明** | 明确写了改了什么（算子/初始化/参数策略/混合策略）+ 为什么本题需要这个改动 | 代码 diff 摘要或改动清单 |
| ③ | **量化效果** | 对照表或对照图（收敛代数 / 计算时间 / 精度等：数字 + 提升幅度） | 对照表（用 `utils/latex_table.py` 出表）+ 对照图 |
| ④ | **公平比较** | 给基线充分调参，不故意弱化基线 | 基线调参记录（网格/次数/选优规则） |

- **禁止自创新算法**；没有基线对照的「新算法」一律不收。
- 无提升 → **如实写明并回退单模型**（不美化、不隐藏）。
- 报告与论文里的每处「提升幅度」都要能回到对照表的同一行。

## 4 · 报告节（四节结构）

### 4.1 模型（Model）

```text
- 对应子问题 / 模型卡号：<问题一 / 卡 1>
- 模型名 + 版本：<…>
- 目标函数/方程（含式编号，与论文/符号表一致）：<…>
- 变量与参数：<符号 | 含义 | 单位 | 来源（与 templates/符号表.tex 同步）>
- 枢纽机制（显式方程）：<…>
- 假设依赖：<A1、A3…（templates/假设表.md 编号）>
```

### 4.2 参数（Parameters）

| 参数 | 基准值 | 单位 | 取值来源（实测/文献/拟合/题给） | 是否进敏感性扫描 |
|---|---|---|---|---|
| <…> | <…> | <…> | <…> | <是/否（否 → 写明理由：题给常数/物理常数）> |

- 种子、容差、迭代上限、超参一律登记在此（可复现的全部信息）。
- ML 任务另附：数据集划分方案（训练/验证/测试或 K 折）、预处理拟合范围（仅训练集，`workflows/05` 硬门禁 6）、各类别指标（均值±标准差、混淆矩阵）。

### 4.3 产物（Artifacts）

| # | 产物路径 | 说明 | 对应论文位置 |
|---|---|---|---|
| 1 | `artifacts/RC-<N>/metrics.json` | <关键指标> | <摘要数字 / 表 1> |
| 2 | `artifacts/RC-<N>/solution.csv` | <解> | <图 2> |
| 3 | `assets/图1-*.png/.pdf/.svg` | <三格式> | <图 1> |

- 图件必须过三闸：`audit_fig` → `figcheck.py` → vision（无 vision 则双闸 + 人检）；论文图统一经 `utils/plot_style.py` 输出。

### 4.4 数值自检（Numerical self-check）

| 检查 | 方法 | 结论 |
|---|---|---|
| 特例 / 已知解 | <n=0、对称、解析可解子问题、闭式解对照> | <通过 / 偏差 <…>%> |
| 量纲检查 | 等式两边量纲一致 | <通过 / 修正记录> |
| 数量级检查 | 结果量级是否符合题目常识 | <…> |
| 「看着合理吗」 | 不合理先怀疑代码（`workflows/05`） | <…> |
| 重跑一致性 | 同命令重跑（固定种子） | <完全一致 / 差异 <…>（查因）> |
| 收敛性（迭代/仿真类） | 重复次数/代数 vs 指标稳定性 | <收敛于 <N> 代 / 样本量 <M>> |

- 不收敛、不理想的结果写进**模型评价**，不删除（`_SHARED.md` §修复动机审计：如实报告不变式）。

## 5 · 模板冒烟要求

| 项 | 要求 |
|---|---|
| 何时跑 | ① 首次使用某个模板前；② 求解前环境自检；③ 赛前一周全量 |
| 命令 | `python smoke_all.py`（`templates-library/`）；缺该脚本时跑模板自带自检或最小用例 |
| 通过线 | 退出码 **rc = 0**；全量冒烟表在案（不存在未跑模板） |
| 失败处理 | 记录失败模板 + 报错 → 换等价模板或手写脚本，并在报告中标 `[降级]` |
| 留证 | 冒烟输出（或表格）随复现卡归档；模板数与 `MODEL_GUIDE.md` README 口径一致（未来兼容门） |
| 环境 | 优先 `<venv>`（Python 3.11）；用系统 Python 必须声明理由与版本 |

## 6 · 论文口径联动

- 报告节里的每个数字都要能在论文里找到同一值（摘要 / 结果表 / 图）；**精度位数全文统一**。
- 「改进」表述与 §3 对照表逐条对齐；论文动词强度与证据强度匹配（`self-review-framework.md` §3.3）。
- 求解输出 → 论文装配的证据链：报告节 → `templates/Claim-Evidence映射表.md` 的「证据」列（可点开的 artifact 路径）。
- 缺陷谱系扫描（`workflows/07`）：结果-代码脱钩 = 七族之一，交付前专查。

## 7 · 自检

- [ ] 交付物最小集齐（脚本 / 报告节 / artifacts / 复现卡 / 敏感性卡）
- [ ] 基线真实跑过（或已声明无改进主张）
- [ ] 改进四件事齐：基线 / 改动 / 量化 / 公平对照
- [ ] 报告节四小节齐（模型 / 参数 / 产物 / 数值自检）
- [ ] 参数来源与种子已登记；ML 任务数据集划分先于预处理
- [ ] 数值自检六项已记录（特例/量纲/数量级/合理性/重跑一致性/收敛性）
- [ ] 模板冒烟 rc=0 已留证；失败项已标 `[降级]` 并说明替代
- [ ] 图表过三闸；论文表格由 `latex_table.py` 生成
- [ ] 所有数字与论文口径一致（精度统一）
