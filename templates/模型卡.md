# 模型卡（E-M3 · 每题一卡）

> **用途 / Purpose**：为每个子问题固化「选什么模型、凭什么选、输入输出是什么、怎么解、怎么验、与谁融合」，是求解（E-M4）与论文建模节（E-M7）的唯一模型口径。
> **对应工作流 / Workflow**：`workflows/04-建模.md`（§题型判断 / §模型选择 / §跨领域迁移 / §模型融合 / §模型建立）；决策矩阵 `references/获奖级方法论/model-selection-matrix.md`
> **门禁指针 / Gates**：`Euler-ENGINE.md` §1 **E-M3**（模型卡）——模型卡齐；**名词清单穷尽**；融合同验证集对照；**无映射模型删除**；§3「建模」行
> **降级 / Fallback**：手工选型 + 决策记录（并标 `[降级]`）
> **填写时机**：选题后 → 首版模型前；模型迭代即更新（禁事后补卡）

### 7 · 验证分级（E1/E2/E3 · 定死口径）

（正本：`workflows/04` §回写 3.1；"可执行"验证的是**什么**——按级区分）

| 级 | 定义 | 判据 |
|---|---|---|
| **E1** | 有方程可代入 | 关键机制可写成分式/方程，含状态变量、参数、量纲 |
| **E2** | E1 + 参数 + 数据需求 | 每个参数有取值依据（实测/文献/量级论证）；写明「哪个数据字段 → 哪个特征/参数」的映射与数据缺位影响 |
| **E3** | E2 + 可立即运行的最小闭环 | 不依赖任何缺失附件即可跑起来的最小闭环（合成数据 / 特例退化 / 解析对照），**并写清数据来源、指标与通过阈值** |

- **全案要求**：至少一处 `[E3]`（M-plan 20–24 档③硬要求）；`E1/E2` 可计入检验设计但不足以单独满足。
- **E3 ≠ 已执行**：E3 仍是设计态；「已执行」为加分观察，不进达标判定。
- **不得把 E3 当「结果正确性」证据**——它只证明变换/方程/输出链在数学上自洽、输出恒合法。
- 各互验条目标注：`[E1]/[E2]/[E3]` + `<设计态 / 已执行>`。

## 8 · 填写说明

1. **一题一卡**：子问题数 = 卡数；问题 2/3/4 的关系（沿用/修正/拓展）在卡首「假设链接」「输入输出」里体现，并在论文节首写衔接句。
2. 先简单后复杂；数据少不上深度学习；能解释优先（`workflows/04` 决策原则 1–3）。
3. 「求解器」列指向**可跑**的模板/脚本；写不出具体文件 = 还没想清楚怎么解。
4. 名词清单**穷尽**：写卡时逐段扫自己草稿，出现的每个模型名词都进表 §3。
5. 卡内数值/方程与代码、论文三处一致；改动任何一处 → 同步改另两处（`templates/符号表.tex` 一致性检查卡）。
6. 迭代时保留旧卡版本说明（`v1 → v2 改了什么、为什么`），不覆盖历史判断。
