## 代码规范

- **先跑通，再优化**：第一版求正确，第二版求效率
- 参数化：换数据就能跑
- 注释：每个函数一句话说清输入输出
- 结果可复现：固定随机种子、记录运行参数
- 输出：结果 + 图表，图表能自解释

## 数据来源与处理交代（硬门禁 5 配套）

- **数据来源表**（放进论文数据部分或附录）：来源 + 获取方式 + 时间范围 + 样本量 + 单位
  - 竞赛附件：注明"来自附件 X"；外引数据（公开数据集/统计年鉴）：引用出处 + 版本 + 日期
- 缺失值、异常值处理规则写成代码步骤，论文禁止"剔除了部分异常值"一笔带过
- 原始数据不改动（留原始副本），处理全部脚本化、可复现

## 算法改进合规（不自创、不空口）

论文要写"改进了 X 算法"时，四件事缺一不可：
1. **基线对照**：原版 X 算法实现出来，同数据、同参数预算下运行
2. **改动说明**：明确写了改了什么（算子/初始化/参数策略/混合策略），以及为什么本题需要这个改动
3. **量化效果**：对照表或对照图（收敛代数/计算时间/精度等，数字 + 提升幅度）
4. **公平比较**：给基线充分调参，不故意弱化基线

禁止自创新算法；没有基线对照的"新算法"一律不收。

## ML 任务纪律（数据集划分 = 硬门禁 6）

- 训练前先划分训练/验证/测试集（或声明 K 折交叉验证，K 常取 5）
- **先划分后预处理**：标准化器/编码器/特征选择只在训练集上拟合，防数据泄漏
- 固定随机种子；报告各折指标均值 ± 标准差，不能只报最好折
- 分类问题附混淆矩阵；类别不平衡要说明处理方式
- 无监督任务（聚类/降维）不做划分，改报轮廓系数/肘部法依据 + 多次重跑稳定性
- 小样本（<1000）优先经典方法；上深度学习必须给理由

## 调 bug 流程

1. 复现：最小可复现用例
2. 定位：print/断点缩小范围
3. 假设：一次只改一个变量验证
4. 修复：改一处测一处

## 结果验证

- 用特例/已知解验证（如 n=0、对称情况、解析可解的子问题）
- 量纲检查、数量级检查
- 结果"看着合理吗"——不合理先怀疑代码
