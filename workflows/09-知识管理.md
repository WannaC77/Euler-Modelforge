### 备份纪律（2026-09-19 立 · 条款化 · 与 M1 同源）

**凡「蒸馏批 / 结构批」改动人格正本文件，改动件 100% 必须带同批备份**，命名与计数口径定死如下：

| 项 | 口径 |
|----|------|
| 命名 | `<原文件名>.bak-<批名>`，批名形如 `distill-20260919` / `personaup-20260919`（批次名 + 日期，无空格） |
| 覆盖 | **改动件 100%**——含新建件之外的一切被改写文件；**不留「仅靠 git 基线」的裸露改动件** |
| 计数 | **由脚本直出**（逐条打印 `BAK <名> (md5=…, <字节> B)` + 末行 `备份件数: N/M`），**禁止手写** |
| 例外 | 无。若某件确有理由不留（如纯新建），须在该批报告内**逐条写明理由**，不得静默 |

**根因（本条款的由来）**：一次蒸馏批的扫描报告里手写「6 份 .bak 全部在位」，实盘 7 份，且两个改动件无同批备份（仅有基线）——**手写计数与裸露改动件是两个独立缺陷**，本条同时封堵。
**验证方式**：改动件集合 ↔ `.bak-<批名>` 文件集合做**双向 set diff**，两侧差集均须为空；计数句只认脚本末行。

### 正本写入门禁（2026-09-19 立 · U6/Q4 裁定 · 与备份纪律同源）

**任何自动流程（定时任务 / 脚本 / 批处理）不得写入正本文件**（判断类动作留给人）。

| 项 | 口径 |
|----|------|
| **禁止面** | `learnings.md` · `workflows\*.md`（含本文件） · `Euler-CORE.md` · `<校准台账>` · `<校准台账>` |
| **允许面** | 自动流程**唯一允许**的写盘动作＝产出「提炼候选报告」，落 `<共享层>/Euler/`（**须入子系统子目录**，不放共享层根） |
| **触发复核** | 报告**待定期复核**（建议每 2 周一次，或与材料批/结构批合并复核；节奏由组织者自定） |
| **复核内容** | ① 是否写入 ② 表述是否需改 ③ 是否并入既有 LS 条目 ④ 归属落点是否正确 ⑤ 复发计数是否准确 |
| **写入执行** | 获准后由 **组织者或受权 agent** 按上方「备份纪律」执行：同批 `.bak-<批名>` + 计数**脚本直出** + **双向 set diff** + 回读校验 |
| **隔离要求** | 本系统报告落 `<共享层>/Euler/`；**与另一套系统（`<共享层>/Vesi/`）严格隔离**——不得合并报告、不得跨读对方 learnings 数据（两套 learnings 分属不同竞赛，复发计数与归属域不同） |
| **未复核积压** | 报告若连续 **3 个复核周期**未被处理，须在下次报告顶部标 `⚠️ 积压 N 期`，不得静默 |

**理由（三态标注：事实 / 推断 / 假设）**：
- **[事实]** 人格正本是高价值低频改动件——任何改动即需同批备份 + 双向 set diff（见上节）。
- **[推断]** 「复发 ≥2 次的判定」「归属工作流文件的判定」属**判断类**工作，非格式类；自动化易把个案误提升为通则。
- **[假设]** 若提炼写错，污染的是**所有后续轮次的判据来源**（LS 条目会被当作既定规则反复引用），回滚成本远高于人工复核成本。

**验证方式**：干跑后 `git -C 数模 status` 须无新增改动（除 job 自身日志）——这是本门禁的**可执行验收式**。

### LS-4 同文件多处修改必须串行（复发 2 次）

- **现象**：① 优化时分发规则到多文件，因并行编辑同一文件产生覆盖——`04-建模.md` 触发词行丢失后重打；② 同文件多处修改若并发提交，后写覆盖先写。
- **根因**：并行编辑的开销不在写入本身，而在**读取→修改→写入之间失去原子性**——两份编辑各自持有旧版快照，后者覆盖前者。
- **执行要求**：
  1. **同一文件的多处修改必须串行**（读完→改完→落盘，再开下一处）；只有**跨文件**才允许并行；
  2. 改规则先**定单点正本**（`Euler-CORE.md` 为规则正本），其余文件只**编号引用**不复述原文，从结构上消除「同一规则散落多文件后不同步」的覆盖面；
  3. 落盘后做**回读校验**：改动前后的文件长度/关键行 diff 必须可解释，不允许「改完发现少了一行」。
