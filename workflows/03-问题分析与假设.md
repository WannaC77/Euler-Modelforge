# 03 — 问题分析与假设

## 何时加载

## 问题重述（Restatement）

用自己的一句话重述题目要解决的问题。**不是抄题**，是提炼出"我们到底要算什么/答什么"。

## 假设清单

每条假设必须：
1. 有现实依据（[事实] 或合理 [推断]）
2. 说明"如果不成立会怎样"
3. 控制数量（通常 5-10 条，多了说明没想清楚）

**常见假设类型**：数据完整、系统近似（忽略次要因素）、参数范围、理想化条件。

⚠️ 冷水④：假设随意 = 没论证、与现实矛盾。每条假设评委都会问"凭什么"。

### 假设书写合规（杜绝空话）

每条假设写成三段式：**具体断言 + 依据 + 违背后果**。

**空话假设黑名单（命中即拒收）**：
- "忽略所有影响因素 / 所有随机扰动" —— 不列出具体忽略了哪些因素就是空话
- "假设数据完全准确无误差" —— 与现实矛盾，且与后文误差分析自相矛盾
- "假设所有参数取理想值" —— 参数取值必须有依据（见 CORE 细节精度）
- "为简化模型，假设……"（不说简化了什么、凭什么能简化）—— 简化必须给出量级理由

**合规示例**：
- ❌ "忽略空气阻力。"
- ✅ "忽略空气阻力（[事实] 单摆 10 个周期内振幅衰减 <2%，阻力效应比重力回复力小一个量级）；若不成立，需引入阻尼项并补充阻尼系数敏感性分析。"

**修正方法**：对每个被忽略因素写清"忽略了什么 → 凭什么能忽略（量级对比 / 数据支持的相关性弱）→ 忽略后如何兜底（模型检验 / 敏感性分析覆盖该参数）"。

## 符号说明

- 统一符号表，全队一致（建模/代码/论文用同一套符号）
- 用 LaTeX 记：`$x_i$ 表示第 i 个...`

## 分析框架

- 把大问题拆成 2-4 个子问题
- 每个子问题对应一个模型 + 一个求解方法
- 画出"问题 → 子问题 → 模型 → 方法"的映射

## Checklist

- [ ] 一句话说清要解决什么
- [ ] 每条假设有依据 + 违背后果
- [ ] 无空话假设措辞（黑名单检查通过）
- [ ] 符号表统一，建模/代码/论文一致
- [ ] 子问题拆分清晰，各对应模型
- [ ] 子问题间数据流已标注（问题一的哪个输出是问题二的输入）
